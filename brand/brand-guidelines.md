## 2. Logo

### Primary Mark

The BrixUp logo is a geometric wordmark built on a construction metaphor:

- **"BRIX" Wordmark:** Bold, geometric sans-serif letterforms. The letters "I" and "X" incorporate a **brick pattern motif** -- the "I" is rendered as a vertical stack of two bricks, and the "X" uses a cross-bond brick pattern at the intersection. This creates a subtle nod to masonry construction visible at larger sizes.
- **"UP" Treatment:** The "U" in "BrixUp" integrates an **upward arrow** into its right stroke. The right side of the U extends upward past the cap height, forming a clean arrow pointing up. This symbolizes growth, stacking, and upward momentum.
- **Monogram:** A standalone "B" with an integrated upward arrow, used as a favicon and app icon.

### Logo Variations

| Variant           | Usage                                          |
| ----------------- | ---------------------------------------------- |
| Full wordmark     | Website header, marketing materials, documents |
| Monogram (B+arrow)| Favicon, app icon, social avatar, loading states|
| Token mark ($BRXU)| Exchange listings, token-specific contexts      |
| Horizontal lockup | Navigation bars, partnership logos              |

### Logo Clear Space

Maintain a minimum clear space equal to the height of the "B" on all sides of the logo. No other visual elements should encroach on this space.

### Logo on Backgrounds

| Background     | Logo Color                     |
| -------------- | ------------------------------ |
| Light (#F8F6F0)| Charcoal (#1A1A2E)             |
| Dark (#0D0D1A) | Off-white (#F8F6F0) or Gold (#D4A843) |
| Photography    | Use the version with highest contrast |
| Gold gradient  | Charcoal (#1A1A2E)             |

## 4. Typography

### Font Stack

| Role     | Font Family     | Weight Range | Usage                                    |
| -------- | --------------- | ------------ | ---------------------------------------- |
| Headings | **Inter**       | 600--800     | Page titles, section headers, hero text  |
| Body     | **Space Grotesk**| 400--600    | Paragraphs, descriptions, UI labels      |
| Code     | **JetBrains Mono**| 400--500   | Token amounts, wallet addresses, code, numerical data |

### Type Scale

```
Display:   48px / 56px line-height / Inter 800
H1:        36px / 44px line-height / Inter 700
H2:        30px / 38px line-height / Inter 700
H3:        24px / 32px line-height / Inter 600
H4:        20px / 28px line-height / Inter 600
Body LG:   18px / 28px line-height / Space Grotesk 400
Body:      16px / 24px line-height / Space Grotesk 400
Body SM:   14px / 20px line-height / Space Grotesk 400
Caption:   12px / 16px line-height / Space Grotesk 400
Code:      14px / 20px line-height / JetBrains Mono 400
```

### Typography Rules

- **Headings** are always set in Inter. Never use Space Grotesk for headings.
- **Numbers and financial data** always use JetBrains Mono for tabular alignment and clarity.
- **Wallet addresses** are always rendered in JetBrains Mono at a reduced size with letter-spacing: 0.02em.
- **Body text** uses Space Grotesk. Its geometric, slightly technical feel bridges the gap between construction and technology.
- **Maximum line length:** 72ch for body text. Use the `max-w-prose` utility.

## 5. Brand Voice

### Personality

BrixUp speaks like **a general contractor who also reads white papers.** The voice is grounded in real-world building metaphors, technically literate but never exclusionary.

### Voice Attributes

| Attribute     | What It Means                                         | Example                                                    |
| ------------- | ----------------------------------------------------- | ---------------------------------------------------------- |
| **Confident** | We know what we are building and we say it plainly.   | "Your brix earn 12.4% APY. Period."                       |
| **Builder**   | Everything is framed as construction, stacking, making.| "Stack your first brix in under two minutes."              |
| **Inclusive** | No gatekeeping. Clear language. Bilingual-ready.       | "New to DeFi? Start here. No jargon, no judgment."         |
| **Direct**    | Short sentences. Active voice. Say the thing.          | "Connect wallet. Stake $BRXU. Watch it grow."              |

### Tone Spectrum

```
Casual ----[---X----]---- Formal
                ^
         Right here.
         Professional but approachable.
         Think: site foreman briefing the crew,
         not a banker presenting to a board.
```

### Language Guidelines

**Do say:**
- "Stack" (instead of "invest" or "deposit")
- "Brix" (instead of "tokens" in casual contexts)
- "Build" (instead of "grow" or "increase")
- "Foundation" (instead of "base" or "underlying")
- "Blueprint" (instead of "roadmap" or "plan")
- "Crew" (instead of "community" or "users")

**Never say:**
- "To the moon" or any rocket/moon imagery
- "WAGMI," "NGMI," "ape in," or any crypto-bro slang
- "Disrupting" or "revolutionizing"
- "Web3" without context (say "onchain" if needed)
- "Not financial advice" as a joke (if legal disclaimers are needed, make them real)

### Bilingual Readiness

BrixUp is designed to serve English and Spanish-speaking communities from day one. All primary UI strings, error messages, and onboarding flows should have Spanish translations ready. The brand name "BrixUp" is language-neutral and does not get translated.

## 8. Motion and Animation

### Principles

- **Purposeful:** Every animation communicates something. No decoration-only motion.
- **Brick-inspired:** Stacking, sliding into place, building upward.
- **Quick:** Most transitions complete in 200--300ms. Nothing should feel sluggish.

### Standard Easings

| Name        | Value                          | Usage                    |
| ----------- | ------------------------------ | ------------------------ |
| Ease Out    | `cubic-bezier(0.0, 0.0, 0.2, 1)` | Elements entering view |
| Ease In     | `cubic-bezier(0.4, 0.0, 1, 1)`    | Elements leaving view  |
| Ease In Out | `cubic-bezier(0.4, 0.0, 0.2, 1)`  | Layout shifts          |
| Bounce      | `cubic-bezier(0.34, 1.56, 0.64, 1)`| Playful confirmations |

### Key Animations

| Animation       | Description                                                |
| --------------- | ---------------------------------------------------------- |
| Brick Stack     | Elements slide up and settle into position with a slight bounce |
| Counter Roll    | Numbers animate from 0 to target value, JetBrains Mono     |
| Gold Glow       | Subtle pulsing glow on staking reward amounts               |
| Foundation Load | Page content builds upward from bottom on initial load      |

## 9. Do's and Don'ts

### Do

- Use construction metaphors consistently -- they are the brand's backbone.
- Maintain high contrast ratios (minimum 4.5:1 for body text, 3:1 for large text).
- Use Gold sparingly as an accent. It loses its premium feel if overused.
- Pair Charcoal with Off-white for maximum readability.
- Use JetBrains Mono for all financial figures and token amounts.
- Test all designs in both light and dark modes.
- Include Spanish translations for all user-facing copy.
- Let the brand breathe -- generous whitespace signals confidence.
- Use the brick-stack animation for loading and staking confirmations.
- Keep CTAs clear and action-oriented: "Stack Now," "Claim Rewards," "Join the Crew."

### Don't

- Don't use the Gold color as a background fill for large areas. It is an accent.
- Don't combine Safety Orange and Gold in the same element -- they compete visually.
- Don't use crypto slang ("wen," "ser," "fren," "gm") in any official communication.
- Don't use rocket, moon, or diamond hand emojis.
- Don't set body text in Inter -- that is reserved for headings only.
- Don't use gradients on text (except the Gold Shine gradient on hero display text in dark mode, sparingly).
- Don't animate more than two elements simultaneously -- it creates visual chaos.
- Don't place the logo on busy photographic backgrounds without a solid backing.
- Don't modify the logo colors outside of the approved palette.
- Don't use drop shadows on the logo.
- Don't use rounded/pill-shaped buttons -- the geometric, slightly squared aesthetic matches the brick metaphor (use 8px radius).
- Don't center-align body paragraphs. Left-align all body text.
